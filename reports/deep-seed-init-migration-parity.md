## Critical Gaps / Risks

1. **Artifact drift currently present in TSK**
   - `cms:check` fails on `.cms/schema.graphql` drift, so generated-state parity is currently broken until generator is re-run and committed.

2. **View-order artifact location mismatch vs NKS expectations**
   - NKS consumers expect `features/keystone/view-order/index.ts`; TSK emits to `.cms/view-order.ts`. Any direct parity tooling assuming NKS path/module will fail.

3. **Seed-vs-init ambiguity remains possible**
   - TSK does document demo-only seed in code comments and separates `db:seed:demo`, but `db:seed` aliases to demo seed and could be misused when testing true init-first parity.

4. **First-admin role bootstrap persistence not explicitly audited end-to-end in this run**
   - Route/mutation plumbing is present; still worth an explicit prisma-mode integration check that first created admin receives dashboard-capable role semantics identical to NKS expectations.

5. **NKS build command environment fragility**
   - Running Keystone build surfaced Next export failures in this local environment; parity test plans that depend on executing NKS build should account for this external blocker.
